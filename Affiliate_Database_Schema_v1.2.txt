Legend & Conventions
Column names use snake_case. Every table has id (uuid, primary key, default gen_random_uuid()). All timestamps are timestamptz and default to now(). Foreign keys are named <table>_id and carry ON DELETE CASCADE unless noted otherwise.

Why 'profiles'?
Supabase manages auth.users internally. Never store extra columns there. Create a public.profiles table linked 1-to-1 via id = auth.users.id and a trigger to auto-insert on signup.

💬  8. comments

The PRD classifies comments as Phase 3 (Scale) and lists the comment system as an Open Question ('Native vs Disqus vs none for MVP'). Building and maintaining native comment moderation, spam filtering, and RLS policies is unnecessary overhead for Phase 1. Skip this migration entirely at launch. Revisit in Phase 3, or adopt Disqus / a third-party widget to avoid the operational cost.

Recommended Setup Workflow
Follow this sequence to avoid relationship or RLS conflicts:
Create Supabase project and note URL + keys
Run table migrations in order: profiles → categories → posts → products → faqs → all others
Add foreign key constraints after all tables exist
Enable RLS on every table; add policies from the table above
Create auth trigger to auto-insert profiles row
Create storage buckets and set per-bucket policies
Add indexes from the Indexing Strategy table
Seed settings table row (id = 1) with site defaults
Connect frontend with VITE_ env vars; test CRUD + RLS with Supabase Studio
